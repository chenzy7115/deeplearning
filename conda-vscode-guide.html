conda 与 VSCode 环境管理手册

从「conda 命令找不到」到「GPU 训练跑通」的完整记录 · 2026-11-02

这套环境现在是什么

这台机器上有三套互相独立的 Python，搞清楚它们是理解后面一切的前提：

Anaconda base
3.14.6
C:\Users\18960\anaconda3
536 个包 · 10.8 GB
conda 环境 dl
3.12.16
anaconda3\envs\dl
118 个包 · 4.93 GB
系统独立安装
3.12.10
Programs\Python\Python312
PATH 里排第一
关键认知：不激活任何环境时，命令行里的 python 指向系统那个 3.12.10，不是 Anaconda。只有 conda activate base 或 conda activate dl 之后，python 才会切到 Anaconda 的对应环境。这就是为什么必须"先激活再干活"。
日常用法就一句话：打开 VSCode → 右下角选 dl 环境 → 新开终端自动激活 → 直接写代码。dl 里已经装好 PyTorch 2.11 + CUDA 12.8，GPU 训练验证通过。

为什么需要虚拟环境

不隔离会出什么事？举个例子：项目 A 需要 numpy 1.26（老代码依赖旧 API），项目 B 需要 numpy 2.5（新特性）。如果全装在同一个 Python 里，只能留一个，另一个项目必然跑不起来。库越多，这种冲突越密集。

虚拟环境的作用就是：给每个项目一套独立的包目录，互不干扰。删掉环境等于删掉目录，干净利落，不会污染系统。

venv 与 conda 的区别

两者目标一样，隔离的层级完全不同。这是最容易被忽略的一点：

venv 是「同一台发动机换个油箱」，conda 是「整车换一套」
对比项venvconda env
隔离范围仅第三方 Python 包包 + 解释器 + C 库 + 编译器运行时
换 Python 版本不行，必须重建可以，一个参数搞定
包来源仅 PyPIconda 仓库 + PyPI
装 numpy下载 PyPI wheel（内含 OpenBLAS）装 MKL 编译版，矩阵运算更快
装 GDAL / FFmpeg / CUDA 工具链pip 常编译失败一条命令预编译好
依赖求解pip 逐个装，不检查 ABI 兼容libmamba 整体求解，保证整条链兼容
创建速度秒级数十秒（要解依赖）
典型体积30–60 MB数百 MB 到 5 GB
切换机制pyvenv.cfg + sys.prefix改 PATH 前缀 + CONDA_PREFIX

一句话记忆

  • venv：只把"第三方包"圈出来，Python 本体还是系统那一个。
  • conda：连 Python 本体、数学库、DLL 一起打包，是个完整可搬运的环境。

两者的适用范围

场景推荐原因
纯 Python Web 后端（Flask / Django / FastAPI）venv依赖都是纯 Python，venv 够用且轻快
小脚本、自动化工具、爬虫venv几十 MB 就能跑，没必要背几百 MB
数据分析（pandas / matplotlib）condaMKL 加速，且 numpy/scipy 版本一致性好
深度学习 / 机器学习conda要 CUDA、cuDNN、MKL 这些非 Python 组件
地理信息（GDAL / Fiona / rasterio）condapip 装这些几乎必失败，需要预编译二进制
科学计算 / 信号处理 / 生信conda依赖大量 C/Fortran 库
需要多个 Python 版本并存condavenv 无法换解释器版本
打包分发、离线部署condaconda-pack 可整包搬走
实践建议：既然已经装了 Anaconda，就统一用 conda 管环境，不要一半 venv 一半 conda。混用最大的问题是"我到底装在哪个环境里"——这类问题排查起来非常耗时。

创建环境

标准写法，指定环境和 Python 版本：

conda create -n 项目名 python=3.12

一次性把常用科学栈装进去（推荐，省得后面一个个装）：

conda create -n 项目名 python=3.12 numpy pandas matplotlib scikit-learn jupyterlab

建完激活：

conda activate 项目名

如果卡在 TOS 条款上

Anaconda 官方源（defaults）从 2024 年起要求先接受服务条款，否则会报：

CondaToSNonInteractiveError: Terms of Service have not been accepted for the following channels.
    - https://repo.anaconda.com/pkgs/r
    - https://repo.anaconda.com/pkgs/msys2

三种解法，任选：

方案 A：接受条款（个人使用免费）

conda tos accept --override-channels --channel https://repo.anaconda.com/pkgs/r
conda tos accept --override-channels --channel https://repo.anaconda.com/pkgs/msys2

方案 B：改用 conda-forge（不涉及 Anaconda 条款）

conda create -n 项目名 python=3.12 -c conda-forge --override-channels

方案 C：配置清华镜像

conda config --add channels https://mirrors.tuna.tsinghua.edu.cn/anaconda/pkgs/main/
conda config --add channels https://mirrors.tuna.tsinghua.edu.cn/anaconda/pkgs/free/
conda config --set show_channel_urls yes
本机的 dl 环境就是用方案 B 建的——既绕开了条款，下载也更快。

环境导出与迁移

# 导出（含精确版本，跨平台会带 build 号，换机器可能装不上）
conda env export > environment.yml

# 跨平台友好：只导出显式安装的包
conda env export --from-history > environment.yml

# 在另一台机器重建
conda env create -f environment.yml

一个项目一个环境吗

不是。正确的划分依据是「依赖组合」，而不是项目数量。「一个项目一个环境」是理想化的说法，照做的话半年能攒出二三十个环境，大部分磁盘和精力都耗在管理环境上，而不是写代码。

一句话原则：当两个项目的依赖能共存时，共用一个环境；当它们互相排斥时，才分家。

什么时候必须新建

信号说明
Python 版本要求不同老项目锁 3.10，新项目要 3.12。venv 做不到，conda 可以
核心库大版本冲突一个要 torch 1.13，一个要 2.11；或 numpy 1.x 与 2.x
需要精确复现论文复现、要交付给别人、要写清楚安装文档
会大量试错装包学新库时容易装乱，隔离起来不怕污染主力环境
两个项目要长期并行来回切换是常态，混在一起必然互相踩

什么时候不必新建

情况做法
临时脚本、算个数、验证个想法直接用 base 或 dl
依赖当前环境都满足直接用 dl，别折腾
同一技术栈的多个小练习共用 dl，MNIST、CIFAR、简单 CNN 都放一起
学习阶段还没有固定项目就用 dl，等真需要分的时候再分

三个阶段的真实布局

阶段环境构成数量
学习期 当前base（工具箱）+ dl（主力）2 个
做项目期base + dl（实验田）+ 每个正式项目一个4–6 个
交付期再加一个「干净环境」，用来验证安装文档是否写得对6–8 个
超过 10 个就该合并了。环境数量本身不是资产，能说清楚每个环境为什么存在才是。如果某个环境你已经三个月没激活过，那它大概率可以删。

命名与体积

名字要能一眼认出用途，别用 test、env1、new、myenv——半年后完全想不起来里面是什么。

# 推荐：项目名，或 技术栈-项目名
conda create -n mnist-demo python=3.12
conda create -n nlp-bert python=3.12
conda create -n py311-legacy python=3.11

查每个环境占多大（PowerShell）：

Get-ChildItem "$env:USERPROFILE\anaconda3\envs" -Directory | ForEach-Object {
    $size = (Get-ChildItem $_.FullName -Recurse -File -ErrorAction SilentlyContinue |
             Measure-Object -Property Length -Sum).Sum
    "{0,-22} {1,8:N2} GB" -f $_.Name, ($size / 1GB)
}

删除不需要的环境

标准流程，按顺序走，别跳步：

第 1 步：确认有哪些、谁在用

conda env list
where python        # 看当前终端指向哪个环境

同时确认 VSCode 右下角显示的解释器不是要删的那个。

第 2 步：需要保留配置就先导出

conda env export -n 环境名 > D:\backup\环境名.yml

以后想恢复：conda env create -f D:\backup\环境名.yml。只是删着玩、确定不要了，这步可以跳过。

第 3 步：删除

conda env remove -n 环境名
删除是不可逆的。环境目录会被整个删掉，里面所有的包、以及你放在环境目录里的任何文件都会一起消失。删之前务必确认项目代码不在 anaconda3\envs\环境名\ 里——正常情况代码应该放在 D:\code\ 下，那种情况不受影响。

第 4 步：清理缓存

conda clean --all

删环境只释放了环境目录本身，安装包缓存还在。本机 pkgs 缓存目前约 6 GB，这一步能一并清掉（之后重装包需要重新下载）。

第 5 步：清理残留

# 检查 Jupyter 里是否还有这个环境的内核
jupyter kernelspec list
jupyter kernelspec remove 环境名

# 检查目录是否真的删干净（删除中途失败会留下空壳）
dir C:\Users\18960\anaconda3\envs

如果目录还在，直接删：

Remove-Item "C:\Users\18960\anaconda3\envs\环境名" -Recurse -Force

删除失败的两个常见原因

现象原因与处理
提示 EnvironmentLocationNotFound名字写错了。先用 conda env list 看准确名字
删除卡住或报文件占用该环境正被终端占用。先 conda deactivate，关掉所有指向它的终端，必要时重启 VSCode 再删
放心删：删除普通环境不会影响 base，也不会影响 conda 命令本身。只有删 base 才会把 conda 一起弄坏——所以 base 永远不要删。

更换 Python 版本

这是 conda 相比 venv 最大的优势，但有个陷阱要说清楚。

方式一：新建环境（推荐）

conda create -n 项目名311 python=3.11
conda activate 项目名311

干净、可控、不会牵连已有环境。缺点是包要重装（可以从旧环境克隆再改版本）：

# 先克隆
conda create -n 项目名311 --clone 项目名
# 再在克隆体上换版本
conda activate 项目名311
conda install python=3.11

方式二：原地改版本

conda activate 项目名
conda install python=3.11
原地换版本的风险：conda 会重新求解整个依赖树，把需要重编译的包换成对应 Python 版本的构建。但用 pip 装过的包 conda 不认识，它们不会跟着重装，通常会直接失效（报 DLL load failed 或 ModuleNotFoundError）。如果环境里 pip 包很多，宁愿新建。

能不能降到任意版本？

可以，但受两个限制：

  • conda 仓库里得存在该版本的构建（太老的版本可能只有 conda-forge 有）；
  • 你的操作系统要支持（Windows 上 Python 3.8 以下已很难装）。
# 先看有哪些版本可选
conda search python

# 指定小版本
conda install python=3.11.9

安装各种库

conda 还是 pip？

情况用哪个说明
科学计算栈（numpy / scipy / pandas / scikit-learn）conda能拿到 MKL 加速版，二进制一致性好
含 C 扩展的地理/图像/AI 库condaGDAL、OpenCV、PyTorch 等有预编译包
纯 Python 库（requests / flask / rich）pipconda 仓库更新慢，pip 更快拿到新版
只在 PyPI 上有的包pip没得选

装 PyTorch（GPU 版）

第一步永远是看驱动支持到哪个 CUDA 版本：

nvidia-smi

输出右上角的 CUDA Version: 12.8 就是驱动上限。装的 PyTorch CUDA 版本不能高于它。然后按版本选索引地址：

# CUDA 12.8（本机用的这个）
pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cu128

# CUDA 12.6
pip install torch torchvision torchaudio --index-url https://download.pytorch.org/whl/cu126

# 纯 CPU 版（没有 N 卡，或只想跑小模型）
pip install torch torchvision torchaudio
PyTorch 的 CUDA 版 wheel 有 2.5–3 GB，且只能从官方源下载，清华镜像没有对应的 CUDA wheel。国内下载可能要几分钟到十几分钟，属正常。

装完必须验证：

python -c "import torch; print(torch.__version__, torch.cuda.is_available())"

输出 2.11.0+cu128 True 才算成功。只有 True 才代表 GPU 可用。

代理

如果本机开了代理软件（本机系统代理是 127.0.0.1:7897），pip 和 conda 默认会读系统代理。也可以在命令行里临时指定：

set HTTPS_PROXY=http://127.0.0.1:7897
set HTTP_PROXY=http://127.0.0.1:7897
注意：环境变量里的代理优先级高于系统代理。如果某天 pip 突然连不上，先检查 echo %HTTPS_PROXY% 是不是残留了一个失效的地址。

在 VSCode 中使用

选解释器（三选一）

  1. Ctrl+Shift+P → 输入 Python: Select Interpreter → 从列表里选带 ('dl': conda) 的那一项。
  2. 点右下角状态栏的 Python 版本号，会弹出同样的列表。
  3. Ctrl+Shift+P → Python: Select Workspace Interpreter，只对当前工作区生效。

选完之后，右下角会显示 Python 3.12.16 ('dl': conda)，新开的终端顶部会自动出现激活提示：

(dl) PS D:\code\deeplearning>

看到 (dl) 就说明激活成功了。此时 python 指向 anaconda3\envs\dl\python.exe。

VSCode 怎么知道有哪些环境

Python 扩展会自动扫描这几个位置：

  • C:\Users\18960\anaconda3（base）
  • C:\Users\18960\anaconda3\envs\*（所有 conda 环境）
  • .venv、venv（项目目录里的 venv）
  • 系统 PATH 里的所有 Python

新建了环境但列表里没出现，执行 Ctrl+Shift+P → Developer: Reload Window 刷新一下即可。

终端没自动激活怎么办

检查这两点：

  1. 设置里 python.terminal.activateEnvironment 是 true；
  2. 设置里 python.condaPath 指向了正确的 conda.exe。

推荐的 settings.json

打开方式：Ctrl+Shift+P → Preferences: Open User Settings (JSON)。

{
    "python.condaPath": "C:\\Users\\18960\\anaconda3\\Scripts\\conda.exe",
    "python.terminal.activateEnvironment": true,
    "python.defaultInterpreterPath": "C:\\Users\\18960\\anaconda3\\envs\\dl\\python.exe",
    "editor.formatOnSave": true,
    "files.autoSave": "afterDelay"
}
配置项作用
python.condaPath告诉扩展 conda 在哪。conda 没进 PATH 时必须配
python.terminal.activateEnvironment新开终端自动激活选中的环境
python.defaultInterpreterPath没有手动选择时的默认解释器
注意 JSON 里 Windows 路径的反斜杠要写两个（\\），否则会被当成转义符。

Jupyter 内核

想用 .ipynb 写代码，需要把环境注册成 Jupyter 内核：

conda activate dl
python -m ipykernel install --user --name dl --display-name "Python 3.12 (dl)"

然后在 notebook 右上角点 kernel 选择器，选 Python 3.12 (dl)。

查看已注册的内核：

jupyter kernelspec list

删除不需要的：

jupyter kernelspec remove dl

常见报错处理

1. conda : 无法将"conda"项识别为 cmdlet、函数、脚本文件或可运行程序的名称

原因：PowerShell 的执行策略是 Restricted，导致 Documents\WindowsPowerShell\Microsoft.PowerShell_profile.ps1 里的 conda 初始化块根本没被执行。而 conda 又没加入 PATH，所以命令不存在。

诊断：

Get-ExecutionPolicy          # 输出 Restricted 就是这个问题
Get-Content $PROFILE         # 看里面有没有 conda initialize 块

修复：

Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned -Force

然后完全退出 VSCode 再重开（旧终端进程还带着旧策略），验证：

conda --version
conda activate base
python -V

为什么是 RemoteSigned：本地生成的文件可以直接运行，从网上下载的脚本必须有签名。这是微软推荐的桌面默认值，安全性和便利性平衡最好。

2. CondaToSNonInteractiveError：Terms of Service 未接受

原因：Anaconda 官方源要求先接受条款。

处理：用 conda tos accept 接受，或者改用 -c conda-forge --override-channels，或者配置清华镜像。详见创建环境一节。

3. pip 报 [WinError 5] 拒绝访问（...RECORD）

原因：Windows Defender 的实时保护正在扫描刚解压的文件，pip 想把临时文件改名时被占用。

处理：直接重跑同一条命令。包文件其实已经解压完整，重试只是补写元数据，通常一次就过。

如果反复失败，加个排除目录（需要管理员权限的 PowerShell）：

Add-MpPreference -ExclusionPath "C:\Users\18960\anaconda3\envs"
4. 从 Anaconda Navigator 启动 VSCode，GitHub 和插件都要重新登录

原因：Navigator 启动 VSCode 时，会把 conda 环境的 PATH、Library\bin 一起注入子进程。结果 VSCode 的 Git 扩展调 git.exe 时加载到了 conda 自带的 libcurl / libssl，HTTPS 和凭据助手容易崩，表现为反复要求登录。

结论：不要用 Navigator 启动 VSCode。VSCode 不需要 conda 环境，用开始菜单、任务栏或 code . 启动即可，环境交给 Python 扩展管理。

5. torch.cuda.is_available() 返回 False

按顺序排查：

  1. nvidia-smi 能不能跑通？跑不通说明驱动有问题，先更新显卡驱动。
  2. pip show torch 看版本号，有 +cu128 后缀才是 GPU 版；没有就是装成了 CPU 版。
  3. 驱动版本太低？nvidia-smi 右上角的 CUDA Version 必须 ≥ 装的版本。
  4. 重装 GPU 版：pip install --force-reinstall torch torchvision --index-url https://download.pytorch.org/whl/cu128
6. 装完包但 import 报 ModuleNotFoundError

九成是装到了别的环境。确认当前解释器：

python -c "import sys; print(sys.executable)"

输出的路径必须是你要用的那个环境的 python.exe。如果不是，说明终端没激活，先 conda activate 环境名。

7. 环境提示 inconsistent / 依赖冲突

通常是 conda 和 pip 交叉安装造成的。先看哪些包状态异常：

conda list

修复尝试：

conda install --revision 0

不行就导出 pip 的包清单，重建环境：

pip freeze > req.txt
conda create -n 新环境 python=3.12
conda activate 新环境
pip install -r req.txt

几条长期有效的习惯

  • 一个项目一个环境，环境名跟项目名一致。别复用一个环境跑三个项目。
  • base 只当工具箱，不要在 base 里装项目依赖——base 坏了 conda 命令本身就不能用了。
  • 装完立刻记下来：pip freeze > requirements.txt，或 conda env export > environment.yml。
  • 遇到诡异问题先问解释器是谁：print(sys.executable) 能解决一半的环境问题。
  • 别用 Navigator 启动 VSCode，两个工具各管各的。
